# v34 · 紧凑评论与原地交流

沿用阅读室的文章材质、场景和主题，本轮把讨论区改成更紧凑的对话布局，并继续完善搜索和私有回复提醒。仅修改论坛；不涉及玻璃海，也未发布到正式站。

## 评论与回复

- 讨论区最大宽度 760px，单条评论随内容自然收窄、最大 660px；头像置于卡片外，作者、时间、正文和操作以较小间距排版。手机视口不横向溢出，输入字号保持 16px。
- 写作框使用独立的不透明表面和边框，不继承文章玻璃的立体倾斜。点击回复时把同一个编辑器移到目标评论下面；目标在视口底部时，仅补足输入框的可见空间。
- 支持能力齐全且服务端明确提供 JSON 协议时，发布在本页插入返回的真实评论片段，同步三处计数；保留原生表单作为降级路径。请求中禁止重复提交和切换目标，允许继续输入。校验失败、网络结果不确定和超时都会保留文字。
- 普通评论、不同回复对象和编辑评论按身份及目标分别保存本机草稿。服务器确认只清除该次提交对应的 token，保留等待期间新输入及较新的跨标签页草稿。
- 回复卡片先展示原句摘要。首次点击“查看原句”展开引用，并以曲线联系可见原评论；原评论不在屏内时，曲线连接本卡片的引用。再次点击或选择“定位到原评论”才滚动；定位后可以返回刚才的位置。原评论在其他页时保留准确的原生分页链接；隐藏内容不会出现在引用中。
- 收起引用、Escape 和页面离开会清理连线，键盘焦点恢复到原按钮。减少动态及暂停动效设置同样生效。

## 搜索与提醒

搜索支持空格分隔的多词 AND 匹配、作者及项目组合筛选。标题与有用的可见正文摘要分别安全高亮；分页保留筛选，字面 `%`、`_`、反斜线不作为 SQL 通配符。隐藏文章与隐藏文本不进入结果摘要。

提醒支持全部/未读筛选、分页、来源文章和原评论摘要；可查看并标为已读、留在列表标为已读、重新标为未读或全部标为已读。权限与 CSRF 校验保留，其他用户不能读取或修改该列表。

## 验证边界

统一检查入口仍为 `scripts/check.py`，新增控制器场景直接加载实际 `community-thread.js` 和 `writing-drafts.js`，覆盖原位补偿、目标草稿、等待期间输入、防重复提交、失败保留、两步引用及原生降级。真实 HTTP 烟测与本机 Chromium 桌面/390px 窄屏单独验收，具体日志位于工作区 `verification/forum-improvements-20261031/v34/`。

本机视口模拟不代表真实手机软键盘、中文输入法、Safari/Firefox 或低性能硬件已经验收；本地不发送真实邮件。本轮没有新增数据库结构，沿用 v33 已演练的回复迁移。
