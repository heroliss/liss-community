# v41 · 淡彩玻璃评论与两种排版

文章讨论区提供“散落”和“列表”两种排版，初次访问默认散落。两者共用淡彩玻璃表面、透明边缘、柔和反光与紧凑文字层次，切换只改变展示，不改变评论顺序、回复对象或草稿。

## 排版与互动

散落模式在桌面采用两列、错落间距和轻微倾角，窄屏改为单列。评论始终保留在正常文档流中，由内容自然撑高，不用绝对定位堆叠。鼠标悬停时玻璃面轻微浮动、摆正，短评论最多放大至 1.04 倍；正文超过 240 字符的评论只轻浮动与摆正，不放大。打开行内回复时，对应玻璃面保持正向，输入区和头像不参与浮动。

列表模式使用整齐的单列玻璃条目，正文区域统一宽度、间距更紧凑。桌面引用保留独立侧栏；散落模式的引用使用紧凑摘要。原句展开、关联连线、再次定位与空白收起沿用既有行为。

每条评论的淡色由评论 ID 稳定计算，同一评论在刷新、分页与异步新增后保持同色；颜色不依赖它在当前页排第几。原文章主题属性继续保留。深浅主题与照片背景分别调整底色吸收层，以保持正文可读。

鼠标浮动仅在精细指针、允许动态及普通颜色模式下启用；减少动态、暂停动态和强制颜色模式取消散落倾斜与浮动。粗指针布局保留可触达的操作尺寸。

## 选择记忆与阅读位置

评论布局单独保存在当前站点的 `localStorage` 键 `liss-thread-layout:v1`，与首页文章卡片／列表偏好分开。有效值为 `scatter` 和 `list`，无记录或非法值回到散落；存储不可用时仍可在当前页面切换。其他标签页的偏好变化及浏览器前进／后退缓存恢复会同步选择。

切换按钮在脚本初始化后显示，以 `aria-pressed` 表达当前选择。没有 JavaScript 时保留可读的默认散落布局，不显示无效切换按钮。

切换时保留当前可见评论的纵向位置，只进行即时滚动补偿，不自动定位或改变焦点。页面变短而接近底部时，使用临时的最小占位保留所需滚动范围；向上阅读或恢复较长排版后释放。模式变化同时清理鼠标反光并重新计算已展开的引用连线。异步新评论自然继承当前模式，发送与草稿流程不变。

## 验收方法

自动化场景位于 `scripts/tests/thread.test.cjs`，覆盖偏好隔离、非法值、存储失败、可见评论位置、页底收缩、引用连线、草稿保留与异步发送。`tests/test_thread_presentation.py` 检查真实页面和异步片段的稳定色值、分页一致性、引用安全及基本结构。构建入口为 `assets/sources.json` 的 `thread` 组。

浏览器验收可按以下顺序进行：

1. 清除评论布局偏好后打开文章，确认默认散落；切换列表、刷新，再前往另一篇文章，确认选择保留且不改变首页文章展示偏好。
2. 在页面中段及临近底部分别切换，比较同一可见评论的顶部位置；保持输入草稿和原句预览展开，再次切换，检查内容、焦点与连线。
3. 悬停短评论，观察轻浮动与适度放大；再测试长评论、行内回复、手机宽度及减少动态，检查遮挡、横向溢出和滚动变化。
4. 发送一条定向回复，确认新评论继承当前排版，成功后输入区收起；刷新及跨页后核对该评论的淡色、引用与顺序。
5. 在深色、浅色与照片背景下检查文字、边缘和引用区，并使用键盘操作切换按钮。

本文件说明实现与验收方法，不替代独立浏览器记录或全量检查结果；实际通过范围以对应源码的检查报告和浏览器记录为准。本轮没有新增数据迁移。
