# 访问统计

管理员登录后在 `/admin/analytics`（网站管理 → 访问统计）查看社区、作品站（Liss Works）和玻璃海的访问情况。

## 记录内容

追踪脚本 `app/static/liss-analytics.js` 在访客浏览器中运行，按批次发送到 `/analytics/collect`：

| 类别 | 内容 |
| --- | --- |
| 访客 | 浏览器内的随机访客编号（localStorage）、首次 / 最近来访时间、完整 IP、User-Agent 及解析出的浏览器 / 系统 / 设备、屏幕与像素比、语言、时区；社区登录用户附带用户名与编号 |
| 访问次数 | 30 分钟无活动视为新的一次访问；来源网址与来源域名、入口页面、utm / from / ref 参数 |
| 页面浏览 | 网址、路径、标题、来源、打开时刻、有效停留（页面可见且 2 分钟内有操作；玻璃海放宽到 10 分钟）、打开总时长、最大滚动深度、视口尺寸、首字节 / 可交互 / 加载完成耗时 |
| 事件 | 点击（文字、元素、链接、坐标）、外链跳转、脚本错误与未处理的 Promise 错误；页面可调用 `LissAnalytics.track('名称', {...})` 记录自定义事件 |

每位访客自动归为一种**类型**，统计页面默认只显示“访客”，可用筛选栏的“类型”单独查看其他类型：

- **本人**：与管理员同一 IP（管理员打开论坛页面或后台的前后 12 小时内）的访问，包括作品站和玻璃海；也包括追踪器见过管理员账号的那些 IP。
- **测试**：Claude 应用内置浏览器，或来自本人 IP 的自动化浏览器。
- **机器人**：User-Agent 自报为爬虫、监控或自动化工具（含 Googlebot、Google-InspectionTool 等）。
- **疑似机器人**：伪装成普通浏览器但有明显破绽——webdriver 标记、软件渲染（无显卡）、posix 语言、800×600 屏幕、自称手机却是电脑屏幕或不支持触摸、未知时区；或同时有两项弱特征（UTC 时区、过旧 Chrome、桌面 Linux、云服务器 IP）且没有任何真人操作。
- **访客**：其余访问。

判断依据显示在访客详情页，可在那里手动改类型（之后不再自动改），或恢复自动判断；规则更新后可在“数据管理”里重新判断全部访客。不登录后台的设备可打开 `?liss_analytics=me` 把该浏览器标记为本人（`notme` 取消）。

**同一访客的识别**：每个浏览器第一次访问时生成一个随机访客编号，保存在该站点的浏览器存储里，之后无论 IP 怎么变都算同一访客；清除浏览器数据、换浏览器或用无痕模式会变成新访客。社区和作品站的存储彼此隔离，所以收集端另外下发一个 `liss_d` 设备 Cookie（`/analytics/` 路径，HttpOnly，两年有效），Chromium 内核浏览器（Chrome、Edge、华为、三星等）会在两个站点都带上它，由此把同一浏览器的社区记录和作品站记录关联起来（访客页“按设备”汇总、详情页“同一设备的其他记录”）；Safari 与 Firefox 会按站点隔离这个 Cookie，无法关联。另外按显卡、CPU、屏幕、时区等计算硬件指纹，相同时提示“可能是同一台设备”（同型号同设置的手机也会相同，只作参考，不参与分类）。同一设备的记录共享本人判断：任一记录被识别或标记为本人，其他记录也算本人。

追踪器与收集端额外记录的信号：
- **浏览器自报**：webdriver 标记、无界面浏览器品牌（userAgentData）、通知权限矛盾、窗口外框尺寸、插件数、`window.chrome` 是否存在。
- **请求头**：Accept-Language、Sec-CH-UA（浏览器品牌）、Sec-CH-UA-Platform（系统）、Sec-CH-UA-Mobile。自称 Safari / Firefox 却带 Chromium 客户端提示、请求头系统与 User-Agent 不一致，都会判为疑似机器人。
- **设备**：系统版本（区分 Windows 10 / 11、macOS 版本）、手机型号、CPU 架构、核数、内存、显卡、触摸点、指针类型、HDR、广色域、色深、配色、减弱动画、网络类型 / 延迟 / 带宽、语言列表。
- **行为**：每个页面的操作次数（鼠标、触摸、滚轮、按键，连续操作算一次）以及是否有过真人操作。

管理后台页面本身不加载追踪脚本。

## 页面

- **概览**：访客 / 浏览量 / 访问次数 / 独立 IP / 平均访问时长 / 平均滚动深度（含与上一同长度时段的变化）、每日或每小时趋势、热门页面、来源、站点分布、入口与离开页面、星期 × 小时热力图、设备 / 浏览器 / 系统 / 屏幕 / 语言 / 时区、热门点击、加载性能、脚本错误。
- **实时**：最近 5 分钟仍在浏览的访客、最近浏览与最近事件，标签页可见时每 20 秒刷新。
- **访客**：按访客或按 IP 汇总，可搜索 IP、访客编号、用户名、备注并排序；访客详情与 IP 详情列出每次访问的页面、停留、滚动与点击轨迹，可为访客添加备注、外查 IP 归属地。
- **页面**：全部页面排行；单页详情含滚动深度分布、来源、页面上的点击与逐次浏览。
- **点击与事件**：事件明细（按类型、关键词筛选）与点击排行。
- **数据管理**：数据文件大小与记录数、不记录的 IP 名单（可一键加入当前 IP）、按浏览器停止记录的链接、CSV 导出、手动清理（某日期之前、某 IP、某访客、机器人与疑似机器人、本人与测试、全部）。清理先预览数量，确认后执行并写入操作记录。

所有页面支持今天、昨天、近 7 / 30 / 90 天、全部和自定义日期，以及按站点筛选。时间按 UTC+8 显示，可用环境变量 `LISS_ANALYTICS_UTC_OFFSET`（分钟）调整。

## IP 归属地与 404

把开源项目 [ip2region](https://github.com/lionsoul2014/ip2region)（Apache-2.0 / MIT）的 `data/ip2region_v4.xdb`（约 11 MB）放入数据目录并 Reload，访客 IP 旁会显示国家、省份、城市与运营商，概览增加“地区”分布（国内按省份）。未放置时功能自动隐藏；更新数据时替换同名文件即可。IPv6 库约 37 MB，免费账户空间有限，默认不放。

概览“404 页面”列出访客打开过的不存在地址（作品站标题含“没有找到页面”，社区标题以“· 404”结尾）及其来源页，用于发现坏链接。

## 存储与维护

数据保存在数据目录下独立的 `analytics.sqlite`（与 `public-demo.sqlite` 同目录），不经过社区的写锁，不修改社区数据库结构，也不会自动删除。删除该文件等于清空统计，下次访问自动重建。

每日备份：在 PythonAnywhere 的 Tasks 中添加每日任务运行 `deploy/daily_backup.py`（用 web app 的 virtualenv Python），它在 `~/liss-backups/daily/<日期>/` 生成核验过的社区备份包和 `analytics.sqlite` 一致副本，保留最近 7 天。异地副本：在自己的电脑上运行 `scripts/pull_forum_backups.ps1`（需先在 PythonAnywhere Account 页面创建 API token 并保存到 `~/.config/liss/pythonanywhere-token.txt`），只下载本地尚无的文件，不删除本地文件。

## 部署要点

- 无新增 Python 依赖。
- IP 取自 `request.remote_addr`。PythonAnywhere 需按[部署指南](public-demo.md)设置 `LIHOU_FORWARDED_FOR_HOPS`，否则所有访客都会显示为负载均衡器地址（网站管理概览页会提示当前识别到的地址）。
- 作品站在生产构建（设置 `SITE_URL`）时自动加载 `https://liss.pythonanywhere.com/static/liss-analytics.js`；本地测试可用 `LISS_ANALYTICS_SRC` 指向本地社区预览。
- 接收端只接受来自社区自身和 `https://heroliss.github.io` 的请求，额外来源可用 `LISS_ANALYTICS_ORIGINS`（逗号分隔）加入；本机预览之间的 localhost 请求自动允许。每个 IP 每分钟最多 240 批，单批最大 64 KB。
- `LISS_ANALYTICS=0` 可整体关闭收集和追踪脚本。

## 服务器日志

“服务器日志”页直接读取 PythonAnywhere 为网站写的访问日志（`/var/log/<域名>.access.log` 及自动轮换的旧日志，最多最近 60000 条），不写入统计数据库。这里能看到不运行 JavaScript、因而不出现在访客统计里的请求：搜索引擎爬虫（Googlebot、bingbot 等）、本站监控（liss-ops 的在线检查与坏链接检查）、请求 .php、.env、wp- 等不存在路径的漏洞扫描，以及 404 与响应时间。可按来源、状态码、范围（页面 / 全部请求）与关键词筛选。其他环境可用 `ANALYTICS_ACCESS_LOG` 指定日志路径。

## 判断依据与网络提示

访客详情页列出全部观察：强证据（一项即判疑似机器人）、辅助证据（两项以上且无真人操作才判）、真人特征（真实显卡、触摸与手机标识一致、请求头与 User-Agent 一致、运营商网络、时区与 IP 所在地一致、有真人操作），以及提示。IP 旁的“机房”表示云服务器 IP；访客列表中的“可能用代理”表示浏览器时区与 IP 所在地不一致，常见于使用 VPN 的真人，不作为机器人证据。
