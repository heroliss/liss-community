# v24 · 有厚度的玻璃与可选择的远景

此版本继续在 `design/community-reading-room` 分支预览。v23 保留为 `community-v23-preview` 对照节点；本轮不修改账号、文章、评论、外观存储、权限、配额、数据库结构或正式站。原生 Flask 路由、表单、CSRF、Markdown 与分页继续承担真实操作。

根据宽镜边与滚动追赶的实际反馈，本版已改为窄边、原生同帧透射方案。旧方案已完成的测试证据独立归档在 `verification/site-next/v24/phases/pre-native-optics`；它们只证明当时记录的源码，不作为后续修改的验证。

## 头像靠近卡面，厚度留在局部

头像在原有位置上增加背面圆盘、独立的环状镜边和贴近卡面的接触阴影。小头像的局部实体厚度约 3.5–5px，较大资料头像约 6–7px；没有通过再次抬高父级来制造悬浮。头像源像素、透明通道与不透明度保持原样，装饰为没有文字内容的伪元素。强制对比模式回到普通可见轮廓。

卡片各方向的默认与鼠标倾斜在前版基础上进一步收敛，保留层高、受光与空间关系。镜边、物体侧面和接收阴影承担体积线索，避免头像游离到卡框之外。

## 折射集中在边角，清晰度留给内容

玻璃正面的磨砂交给浏览器原生 `backdrop-filter`，与页面本身的滚动合成。主体保持约 24px 局部厚度，由 80° 斜侧壁、背面、接触阴影和窄倒角表达；正面轮廓为 1px，材质倒角约 3.5px，不再用宽镜框挤占内容。手机文章卡厚度为 12px，紧凑回复为 8px / 手机 6px。

之前逐卡片复制邻近背景的位图折射已放弃。新方案不保留 15Hz 的镜边取景缓存，不让旧画面在滚动时追赶正文；共享材质 shader 只承担受光、微表面和倒角反射。

这是原生透射与艺术化反射的组合，不是光线追踪或物理准确的玻璃折射。它不读取用户图片或正文像素，不声称模拟全部内部光路、色散或任意前景的真实折射。原生背景与玻璃取景共享当前浏览器画面，背景本身可保留轻微缓动视差。

### 分档依据

本次实际抓取的 [StatCounter 全球桌面统计](https://gs.statcounter.com/screen-resolution-stats/desktop/worldwide)显示 2026 年 9 月样本中：1920×1080 约 28.07%、1536×864 约 10%、1366×768 约 7.95%、1280×720 约 4.71%、2560×1440 约 3.95%。[手机统计](https://gs.statcounter.com/screen-resolution-stats/mobile/worldwide)中，414×896、360×800、384×832 与 390×844 是常见报告档位。这些是该统计样本，不是对所有设备的完整盘点。

手机表中的 360–414 宽度不能直接当作图片所需的物理像素。浏览器版式使用 CSS 像素；[MDN 对 DPR 的说明](https://developer.mozilla.org/en-US/docs/Web/API/Window/devicePixelRatio)区分了物理像素与 CSS 像素，同一窗口也可能因缩放或移动到另一块屏幕改变 DPR。因此本版本的 960/1440/1920/2560/3840 是**可下载图源档位**，不是五个手机或 CSS 布局断点。

自动选图先以原图宽高比计算带余量视窗的 cover 放大系数，再乘当前 DPR，按所需的图像宽和高选择最小足够文件。纵向长卷、正方形地月照片与横向海岸各自计算，不能只看窗口宽度；超出原图能力时保留最高真实档位并记录源分辨率限制。实际抓取文本与解析表留在 `display-primary-sources.json`、`statcounter-top-resolutions.json` 及原 HTML 中。

NASA 原始文件、官方元数据、来源与使用规范记录，及每个编码文件的尺寸、字节与 SHA，集中保存在工作区 `verification/site-next/v24/background-assets`。NASA 素材的说明仅针对选取的官方任务照片；不把所有 NASA 图片、标志或第三方素材一概称作无条件公有领域。相关要求见 [NASA 媒体使用说明](https://www.nasa.gov/nasa-brand-center/images-and-media/)。

## 内容与操作仍是原生平面

代码块采用带局部吸收的透明阅读面，保留自身横向滚动和原生文本；普通图片不被统一加透明度，有源 alpha 的图片自然透出。输入区增加局部受光与边框动感，实际输入、标签、光标、选字及工具栏不旋转。登录/注册、写作、编辑资料与个人主页在共享玻璃语汇下分配不同的场景重心；密码显隐、代码复制等增强不替代原生字段与内容。

背景设置放在浏览器原生顶层，账户菜单继续使用明确的头部层级，避免点击穿透到三维帖子。页头页尾提供一致可找到的操作，减少动态、暂停、触屏和强制对比各自有退化路径。

## 性能与验证边界

不为每张卡片创建独立 WebGL 上下文。材质继续共享 atlas；程序背景不请求图像并关闭装饰场景 GL，照片场景才保留三组有限几何。背景位移由原生图片 / SVG 在每个需要的动画帧更新，装饰几何上限 30Hz；新交互使用有限帧，停稳后停止。已移除逐卡取景、15Hz 位图缓存、隐藏浮点合成画布与长卷画布。文字和前景维持浏览器自身清晰度，磨砂本身的浏览器合成开销仍需实际测量。

旧方案的 48MB 只约束其背景合成颜色平面，不是整个网页或总 GPU 内存预算；新版已经移除该合成缓冲。3840×3840 的图片解码为 RGBA 就约占 59MB，尚未计入浏览器内部纹理、深度/MSAA、材质 atlas、前景图片和驱动开销；图片文件只有约 121KB 不意味着其解码内存同样小。按需选档与限制保留图像的数量同时服务于流量、解码和内存成本，`decodedImageBytes` 也只记录当前背景的估算值。

本版本继续使用 SDR 图像与网页颜色，不声称启用显示器 HDR。材质 shader 保留静止的物体空间细微抖动以缓和自身的 8 位色阶，不使用持续闪烁的噪声动画；原生背景图的位深仍受素材、浏览器与显示链路约束。

`pre-native-optics` 阶段已运行全部原始 252 项测试：251 项通过、1 项原有 Selenium opt-in 跳过，零失败或错误；另有页面状态 246/246、保护项 169/169、22 份模型 / 表单 / 迁移文件不变。原始日志保留 ResourceWarnings。套件与页面状态当时的源码快照一致；归档时已改动的 `materials` / `surfaces` 文件明确记录差异，未冒充旧受测源码。

最终原生方案在实际浏览器中检查了桌面与 320/390px 窄屏、深浅色正文与代码、个人主页及资料/登录/注册/写作布局。原生合成账号登录/退出、密码显隐、代码精确复制、全屏编辑器、图片模态关闭与焦点返回均保留。背景选择关闭后返回原触发按钮；无图模式刷新后没有 `/scenes/` 请求，且装饰背景 GL 为零。1920×1080 CSS 视口、DPR 2 的测试自动选到 3840×3840 档；带相机余量后的需求超过最大图源时，仍如实记录 `sourceLimited`。

所有测试和截图进程结束后，在本机 1440×1000、DPR 1、6 个可见材质面下进行了三轮相同的鼠标移动与滚轮输入采样。每轮约 3.4 秒，RAF 回调频率为 137.54 / 137.83 / 137.24 FPS，95 分位帧间隔约 7.1 / 7.1 / 7.2ms，没有记录到 JavaScript 长任务或渲染器错误。它是当前硬件与浏览器环境的短时结果，不是所有设备的性能保证，也不是 GPU 实际呈现帧数或受控旧版增速比。该场景只使用一个背景 GL 和一个共享材质 GL，逐卡背景取景与旧合成缓冲为零。

在连续三次确认无待处理帧后，再观察 1.105 秒，原生背景、装饰几何及材质绘制计数增量均为零；系统减少动态模式同样停止排队。原始数据见 `native-performance-*.json`、`native-idle-final.json`，首次探针的工具超时也单独保留，未作为性能失败或通过数据。

Taste 还独立检查了首页与长文的 1440 / 768 / 390 三宽截图。原始审美检测没有全部通过：渐变、立体阴影与文字投影等触发其偏平面化的默认规则；这里按用户明确要求保留玻璃与立体方向，没有隐藏检测结果。实际截图另行检查文字、图片边界与横向溢出，未发现新增阻塞。详情保留在 `taste-native-final-review.md`。
